SAP调用BAPI做生产订单261扣料

发表于 2026-10-19 Waline： 本文字数： 1.3k 阅读时长 ≈ 2 分钟

📌 摘要：同事在用 EWMS 系统调用生产订单 261 扣料接口时发现，当生产订单预留存在两行相同物料时，系统只找第一行扣预留占用数量，且不校验扣料数量是否超过预留数量，导致第二行预留未被释放。本文记录问题根因，以及从「手动处理」到「接口方案调整 + SE11 结构加预留行号 + 改造扣料代码」的完整根治过程。

一、问题背景

上周，同事使用 EWMS 系统调用生产订单 261 扣料接口时发现：

  • 生产订单预留中有两行相同物料时，系统会直接找第一行物料扣预留占用数量，且没有校验扣料的数量是否超过了该行预留的数量。

二、原因分析

查看接口结构后发现，问题出在预留定位方式上：

接口中没有预留号、预留行号字段，而是通过 生产订单号 + 物料号 去 SELECT 预留单号，再赋值调用 BAPI 扣料。

由于该工厂启用了 MRP，扣料没有精确到预留行，相当于第二行的预留没有被释放，最终导致异常。

三、解决方案

第一步：处理当前订单

先手动勾选第二行的「发货完成」标识，解决当前这张订单的问题。

第二步：调整接口

调整接口逻辑，改由外围系统传递预留号 / 生产订单号 + 预留行号，扣料时精确定位到预留行，精确释放预留。

第三步：改造代码落地

3.1 SE11 新增预留行号字段

在结构 ZST_PACK_ORDER_ISS_ITEM 中新增 RSPOS（预留行号） 字段：

▲ 图 2：组件列表新增 RSPOS（预留/相关需求的项目编号）字段

3.2 修改扣料代码

在扣料函数（ZTYN_MS_ORDER_ISS2）中，仍按 生产订单号 + 物料号 从 RESB 查出预留单号（RSNUM），但预留行号直接使用外围系统传来的 RSPOS：

▲ 图 3：扣料代码——SELECT 预留单号，预留行号用外围传入的 RSPOS

💡 插曲：这里之所以还要再去 SELECT 一次预留号，是因为之前的生产订单同步接口没有把预留号同步给 EWMS。

四、测试验证

今天同步做了另外一个测试：

  • 如果传输的物料不传预留号、行号，只传物料号，也是可以扣料的；
  • 但此时走的是计划外扣料，无法对应到具体预留行。

五、经验总结

  1. 生产订单 261 扣料时，预留定位必须精确到预留号 + 预留行号，仅靠「生产订单 + 物料号」定位，多行相同物料时容易扣错行。
  2. 启用 MRP 的工厂，预留行未释放会造成预留占用异常，需及时处理。
  3. 外围系统接口设计时，建议由外围系统传入预留号 / 预留行号，从源头避免扣错。
  4. 物料数量调整，优先用 CO02 修改 BOM 数量，而不是新增预留行。
